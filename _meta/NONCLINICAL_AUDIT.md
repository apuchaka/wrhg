# Non-clinical files inside the corpora — enumeration, 2026-08-30

## Why this exists

`md_files()` applied `SKIP_FILES` only at vault root, so anything inside a corpus
directory was treated as clinical content unconditionally. The scan therefore wrote
provenance frontmatter and conflict counters into Corpus B's build queues, asserting
a trust level about clinical claims those files do not contain. It happened twice
before anyone noticed, and it was found by a `git status` hook rather than by any
check the tools ran.

A file wrongly labelled clinical is also a candidate **merge destination**, and the
new-file stop would not catch it — the file already exists. So this was enumerated
before the C1–C7 merge started, not after.

**Enumerated from the directory, not from the skip list.** Deriving the answer from
`SKIP_PATHS` would only restate what was already known.

## Result

**240 files walked. Exactly 2 are non-clinical. Both were already excluded and stripped.**

| File | Evidence | Disposition |
|---|---|---|
| `Corpus B/00_BUILD_QUEUE.md` | own line 1: "This is a queue, not clinical content" | in `SKIP_PATHS`; four frontmatter lines stripped (PR #28) |
| `Corpus B/00_BUILD_QUEUE_v2.md` | own line 1: "This is a queue, not clinical content" | in `SKIP_PATHS`; stray counters reverted before commit |

No third file. No further strips were needed.

## The three passes, and what each one missed

### 1. Self-declaration — the only pass that worked

Broad regex over the first 4 000 characters of every file: *not clinical*, *this is a
queue/list/index/map/tracker*, *no clinical content*, *do not study*, *index/stub/
template file*, *generated. do not*, *infrastructure*, *build queue*, *coverage report*.

**3 hits, 2 confirmed, 1 dismissed.**

- `Corpus B/A8_Foreign_Bodies_by_Site.md` — **dismissed.** Matched `build queue`, but
  the file is 4 499 words of dense clinical content; every hit is inside a Step 31
  provenance note of the form `` `TODO:link — GER4 Safeguarding & forensic (unbuilt;
  was P3 in build queue v1)` ``. A reference *to* the queue, not a declaration of being
  one. This is rule 3 working as intended.

### 2. Structural (clinical-term density) — FAILED TO FIND THE ANSWER

Clinical-vocabulary density per 1 000 words across all 240 files.

**`00_BUILD_QUEUE.md` ranked 10th of 240 at 14.9/1000 — mid-pack, not an outlier.**
Nine genuine clinical files scored lower. Had the self-declaration pass not existed,
this method would have returned a clean result on a file that is unambiguously not
clinical content. It is recorded here as a **demonstrated blind spot**, not as
corroboration.

It also produced a false negative in the other direction:
`Corpus A/11_08c_Ortho_-_Fracture_Types_and_Pathological_Fractures.md` scored **zero**
clinical terms and is genuine clinical content — its vocabulary is fracture-pattern
specific (*oblique, comminuted, segmental, spiral, greenstick, Wormian*) and matched
none of the generic word list. Dismissed on reading the file.

### 3. Filename convention — found both, plus 8 dismissed

Per-corpus filename patterns measured from the directory. **10 outliers, 2 confirmed,
8 dismissed:**

`03a_Anaesthetics_Primer` · `14a-1_Psych_-_Substance_Misuse` ·
`14a-2_Psych_-_Overdose_and_Poisoning_Management` ·
`Clinical-Process-EBM-Consent-Capacity` · `Communication` · `Examination` ·
`History-Taking` · `Investigation-Interpretation`

All eight are clinical, and all eight are the case CLAUDE.md §1.10 already names:
"Corpus A is not purely disease-organised — it holds investigation, history and
examination files." Confirmed by reading each file's opening lines.

## Honest limit

Two of three methods failed on the known answer. The claim this audit supports is
**"clean against self-declaration, structure and naming, all three run against the
real directory"** — not "no other non-clinical file exists." A file that is
infrastructure, says so nowhere, is named conventionally and carries clinical-looking
prose would pass all three.
